# Shared API contract 2.0.0

Status: **APPROVED / PROVISIONAL OPERATIONS IMPLEMENTATION-BLOCKED**. Specification revision 2.0.0-draft.3 (B02-r3), owner-approved under G1 ledger v3 for bundle SHA-256 `666af99f…bfb55`. Authority: BrainIA-Backend planning bundle; consumers: BrainIA-Backend and BrainIA-Mobile. This is a normative interface specification, not an implemented API. Existing `/api/v1` remains available during migration. The thirteen provisional operations remain implementation-blocked: mobile implementation, including credentials/consent/capture/UI changes for them, still requires their own gate evidence and is not authorized by this approval. Safety containment on a live release requires separately authorized action.

## Distribution and compatibility

Backend contract worker publishes the approved OpenAPI 3.1 + JSON Schema + fixtures + checksum bundle in `contracts/brain-ai/2.0.0/`. Mobile contract-import worker imports those exact bytes into its own repository and verifies SHA-256 after approval; backend workers never copy into mobile. Contract validation precedes generation of TypeScript/Kotlin models. No runtime imports across repositories. SemVer: optional response fields/minor enum extension with unknown handling -> minor; changed required fields/identity/state semantics -> major; clarification -> patch. Unknown response enum values show unknown state and never imply acknowledged/succeeded. Requests reject unknown fields except explicit `content.raw` extension object.

Approval ledger entry must contain version, canonical artifact hashes (spec/schema/fixtures), backend reviewer, mobile reviewer, human approver, timestamp, auth and retention decisions, approved capabilities, and expiry/change policy. A textual draft or worker completion is not approval. G1 can approve a subset only if omitted mobile feature tasks remain blocked. Any material wire change invalidates downstream approval until reviewed. Live capabilities endpoint, not app version alone, determines v2 support. Remove v1 only after >=30 days with zero known active v1 devices and explicit retirement approval; offline devices remain an open migration concern.

## Authentication and HTTP conventions

HTTPS mandatory. Initial strategy: registered revocable owner-bound device credential using `Authorization: Bearer <opaque-device-token>`. Server maps token hash to principal/owner/scopes; token contains no trusted caller-supplied owner. Legacy client API key accepted by v1 only after mapping to same principal; reject mismatched `x-brainia-client-id`, do not use it as filter authority. Never ship global backend/admin or Supabase service credentials in mobile. Device credential enrollment occurs out of band through controlled admin issuance in first release; OAuth/user-session enrollment is deferred, not silently implemented without review.

All routes below require authenticated owner and listed operation scope. Admin/cron auth uses dedicated exact endpoints and distinct credential class. Caller cannot provide owner_id/client_id in bodies/queries. 401 pauses queue and prompts reauthentication; 403 pauses relevant operation; 404 hides foreign IDs. `X-Request-Id` is an opaque trace ID, no personal content. `Cache-Control: no-store` for personal responses. `Content-Type: application/json; charset=utf-8`. JSON timestamps RFC3339 with explicit offset; responses UTC. Dates never use device locale formatting. Opaque IDs 1–160 characters; source keys 1–512, revision/delivery IDs UUID strings. Decimal regex `^-?(0|[1-9][0-9]*)(\.[0-9]{1,6})?$`, no exponent/NaN/floats. Cursors opaque, owner/filter-bound, exclusive; default 50/max100 results.

Errors use `{error:{code,message,requestId,retryable,details?}}`; details contain field paths/limits/expected versions, never secret/personal payload. Common codes: invalid_request(400), unauthenticated(401), forbidden(403), not_found(404), identity_conflict or version_conflict(409), payload_too_large(413), unsupported_contract(422), fingerprint_mismatch(422), rate_limited(429), unavailable(503). 429/503 supply Retry-After; retries preserve identity fields. Policy-disabled capture returns 403/source_disabled, not a success receipt. Server does not accept-and-drop evidence. 5xx before acknowledgement may have committed: replay same delivery ID.

Envelope required fields: all above except source timestamps nullable. producerSequence is a positive int64 decimal string allocated in durable source storage, not a JavaScript number. content.type enum notification|email|receipt|note|activity|location, per-type schemas below. Item <=64KiB UTF-8 including raw, body <=48KiB, title <=1KiB; original oversized evidence must not be silently truncated and labelled complete. Queue item becomes needs_attention, with explicit user decision or separately versioned attachment support. Limits are part of G1 approval.

Common content shape is strict `{type,title:string|null,body:string|null,raw:object}`; notification additionally requires packageName. Email adds providerMessageId, providerThreadId nullable, sender, recipients array, attachmentRefs array; no OAuth tokens. Receipt adds merchantText nullable, reference nullable, attachmentRefs; values still extracted/validated backend-side. Attachment reference DTOs are documented, but both attachmentRefs arrays are empty-only (`maxItems: 0`) until a connector is approved; non-empty arrays are rejected. Activity adds signalType, intervalStart, intervalEnd, confidence nullable and observed/inferred marker. Location adds latitude/longitude decimal strings, accuracyMeters nonnegative decimal, intervalStart/end, provider; no inferred activity in observed field. Note has no extra required fields. All observations require a source instance with matching authorized type. JSON Schema worker must enumerate full strict per-type variants and invalid examples before approval; no generic raw payload may bypass consent/limits.

## Fact, financial, correction and answer DTOs

Fact contract (Zod discriminator plan): strict common object `{id,field,dataType,value,revisionId,evidence:{pointer,start?,end?,excerptHash},method,extractorVersion,modelRevision:null|string,confidence:0..1,uncertainty:{reason,candidates}?,validationStatus,userCorrectionStatus}`. dataType enum string|decimal|currency|timestamp|boolean|entity_ref; value type must match discriminator, decimal never float. method deterministic|provider_structured|llm|user; validationStatus proposed|validated|ambiguous|rejected|user_confirmed; userCorrectionStatus none|active|revoked. Span bounds must be paired and UTF-16 verified. Confidence is not an authorization or confirmation threshold. Model output passes Zod and source evidence validation before canonical selection; title/merchant without span stays proposal. Balances and totals are separate field/role facts. Conflict response preserves both fact IDs and review reason.

Financial DTO: `{id,canonicalEventId,version,kind:expense|income|transfer,lifecycle,amount:"125.50",currency:"UYU",currencyStatus,occurredAt,postedAt:null|string,merchant:{id?,label,verified},accountId:null|string,evidenceCount,revisionCount,evidence:[{observationId,revisionId,factIds,role,strength}],reviewReasons:[]}`. Signed adjustments are returned separately; amount is nonnegative base magnitude, summary applies kind/adjustment sign. No totals from evidenceCount. Summary `{from,to,asOf,totals:[{currency,income,expense,refunds,net,transactionCount}],excluded:{ambiguous,unsupported,pending},conversion:null|{rateId,rate,asOf,provider,toCurrency,amount}}`. Account scope validated on every request. All fields with currency include explicit currency or null/unknown status; no implicit USD/UYU fallback.

Correction POST `{idempotencyKey,target:{type:"fact"|"event"|"transaction",id,expectedVersion},field,value,scope:"once"|"rule",ruleMatch?:{sourceInstanceId,exactDescriptor},reason?}`. Allowlist field/value schemas; ruleMatch mandatory for rule; server previews affected count and returns review requirement if broad. Result `{correctionId,version,status:"applied"|"review",reprocessing:"queued"|"not_required"}`. Client cannot submit arbitrary SQL/ownership/lifecycle graph mutation. Rule application and undo have audited versions. Existing correction endpoints remain adapter-compatible.

Query result `{queryId,status,answer:null|string,structuredTotals?,evidence:[{id,observationId,revisionId,factId?,pointer?,permittedExcerpt}],claims:[{text,citationIds,verification:"supported"|"uncertain"}],limitations:[],coverage:{exhaustive:boolean,retrievalStrategies:[],timeRange},modelCalls,elapsedMs}`. Uncertain claims are labelled or withheld; no answer presented as verified before verification. Server never emits source text excluded by owner/policy; recheck at response time. Stored answers become unavailable/redacted after source deletion. Evidence text is data, not model/tool instructions.

Episode DTO `{id,type:"shopping"|"work"|"research"|"travel"|"purchase_delivery"|"appointment",version,status:"proposed"|"active"|"closed"|"review"|"retired",startAt,endAt:null|string,timeUncertaintyMs,confidence,members:[{canonicalEventId,revisionId,role,confidence,evidenceIds}],summary:null|{artifactId,revision,text,citationIds},reviewReasons:[]}`. Membership is a supported association, not causality. List response `{items:[Episode],nextCursor:null|string}`; detail additionally includes `priorRevisionIds` and `activeCorrectionIds`. Generic corrections support `target.type:"episode"` with fields membership_include/membership_exclude/split/merge, expectedVersion mandatory, typed ID payloads and source-owner checks; broad merge/split returns review preview before application. B02 must include this feature in G1 bundle or mark it excluded and keep M07 episode implementation blocked until an approved version includes it. No unapproved extension by a mobile worker.

Policy update response `{sourceInstanceId,policyVersion,enabled,externalModelsAllowed,externalEmbeddingsAllowed,retentionDays,effectiveAt,cancelledPendingWorkCount}`. Source disabled denies new capture/processing/retrieval, retains stored evidence until deletion; external processing disabled retains eligible local owner retrieval. A derived result requires all supporting sources to permit its requested purpose. Delete mode `derived` retires interpretations/indexes/artifacts but preserves raw evidence and blocks automatic rebuild until explicit reprocess consent; `evidence` removes raw content and descendants dependent solely on it, recomputing conclusions from remaining evidence; `all` removes both within selected scope. Deletion never deletes other owners' evidence. All modes tombstone their selected domain before cleanup and block stale jobs. Export response `{snapshotId,items:[{type,id,record}],nextCursor}`; type allowlist observation/revision/fact/correction/event/transaction/episode/artifact, each record uses corresponding approved DTO and excludes provider credentials. Cursor expiry returns 409/export_snapshot_expired; restart is explicit.

## Mobile durability, privacy and conformance

Local outbox transactions persist source mapping, sequence, fingerprint and pending item before scheduling. Delivery states pending -> in_flight -> acknowledged; failures -> retry_scheduled|blocked_auth|needs_attention; process restart reclaims in_flight. Exponential full jitter 2s..30min honors Retry-After; WorkManager connectivity constraints, unique drain work, periodic health separate from delivery. Listener callback must not wait for HTTP. Removal is a source lifecycle revision with no financial inference. Force-stop/permission loss cannot be defeated; surface health gap and reconcile available notifications on next permitted execution. Bounds/security/retention follow PRD. Native and JS credentials share one secure abstraction; never mirror plaintext secrets in preferences/logs/backups.

Contract fixture obligations for both repositories: valid/new/duplicate/update/reordered/A-B-A/reused-key/removed envelopes; matching fingerprints including Spanish accents and surrogate pairs; wrong owner, revoked source, private provider prohibition; malformed 2xx, 409, 429, 503, partial batch; decimal/currency/refund; stale correction; deletion replay. Backend publishes bytes, mobile tests against those exact bytes. Shared verification is split into one worker per repository; reviewers exchange receipts/reports through Supervisor, never filesystem write access across repositories.

## B02-r3 resolved decisions and provisional operation schemas

The published bundle is **APPROVED / PROVISIONAL OPERATIONS IMPLEMENTATION-BLOCKED** (B02-r3, ledger v3). `open-items.json` records `openDecisionCount: 0` and `approvalReady: true`: the seventeen owner-confirmed wire decisions are encoded, and the thirteen provisionally authorized operations carry strict schemas and positive/negative fixtures with `implementationBlocked: true`. `POST /api/v2/deletions` remains intentionally excluded from OpenAPI and mobile implementation; only its future response DTO is published. **M07 episodes, email/activity capture and connectors remain blocked.** A successful `npm run contracts:verify` verifies immutable artifact bytes and fixture expectations; it does not authorize the thirteen operations' implementation or certify runtime behavior. This B02-r4 metadata reseal changes no wire, schema, OpenAPI path or fixture semantics.

B02-r3 corrects the B02-r2 review findings without widening any owner-approved decision: attachment arrays are empty-only again, the batch maximum is the owner-approved 1..100, the summary query rules are structurally encoded in `FinancialSummaryQuery`, and the email callback accepts a provider `error` without `code` with dedicated 302 `Location` fixtures. Six wire values were explicitly confirmed by the owner on 2026-10-18 and are recorded in ledger v3: activity `signalTypes`, event `eventType`, Fact `field`/`visibility`, episode membership roles, the connector `returnRoute`, and the `ISO4217-CLDR-45` registry label with its confirmed UYU/USD subset.

Strict content schemas now cover notification, note, receipt, email, activity and location. `activityMarker` is `observed|inferred`, `signalTypes[]` is the closed allowlist `still|walking|running|cycling|driving|transit|unknown`, `interval` is `{start,end}` with `end>=start`, and `confidence` is 0..1. Email uses structured `{address,displayName?}` with 320/256 character bounds. Attachment refs are opaque `{refId,provider?,mimeType?,sizeBytes?,sha256?,expiresAt?}`, but both `Email.attachmentRefs` and `ReceiptContent.attachmentRefs` are **empty-only** (`maxItems: 0`) until connector approval; non-empty arrays fail validation. Error `details` is a strict union discriminated by `kind` (`field_errors`, `retry`, `conflict`, `blocked_category`); free-form details are rejected.

`raw` remains an explicit extension object but is source-allowlisted: notification accepts only `packageName,title,body`, receipt/wallet accepts only `amount,currency,merchant,transactionType`, and note/email/activity/location raw objects must be empty. Unknown or credential-shaped keys are rejected. Raw payloads still require approved source policy; schema acceptance cannot grant consent.

Source timestamps remain required nullable wire fields, capabilities are bearer-protected with no credentials in the response, receipts are queued-only, batches are non-empty 1..100 (index 0..99) with ordered `index` and nullable `deliveryId` on malformed items, and summary requests require `from`/`to` with `from<=to` and at most a 366-day range. `conversionTo` requires `fxRateId` and must belong to the approved currency registry (confirmed UYU/USD subset). Capabilities advertise the feature gates `email,activity,location,episodes,connectors` as fixed `false` in this revision and pin `currencyRegistryVersion: "ISO4217-CLDR-45"`. All body fields are required unless explicitly optional; response unknown-enum handling must still show unknown safely. JSON objects must have unique member names; invalid Unicode, including lone UTF-16 surrogates, is rejected. Transport parsers must reject duplicate JSON names before canonicalization (the fixture verifier operates on already-parsed values).

### Fact and deletion decisions

`Fact` is a strict discriminated union on `factType` (`string|decimal|currency|timestamp|boolean|entity_ref`) with a typed `value`, `field` from the closed allowlist `merchant,amount,currency,occurred_at,posted_at,description,account,category,reference,title,sender,recipient,location,activity,entity,quantity,unit,status`, UTF-16 `evidence.start/end` (paired, `end>start`) and `excerptHash`, `confidence` 0..1, `extractorVersion`, `visibility: visible|internal`, `validationStatus`/`userCorrectionStatus`, and typed uncertainty candidates. No generic value placeholder exists. Evidence must reference an existing event at runtime.

Amounts use at most 18 integer and 6 fractional digits; `ConversionRate` uses at most 12 fractional digits. Currency is a 3-letter ISO 4217 code; the registry is pinned by `currencyRegistryVersion`, rounding is half-even to the CLDR exponent, and unsupported codes return `unsupported_currency`. The approved summary registry subset is `USD`/`UYU`; other codes are rejected by `CurrencyRegistry` until the owner expands the confirmed registry. Only UYU/USD summary fixtures are confirmed. Deletion creation remains excluded; its approved 202 shape is `{deletionId,state:"queued",createdAt,remainingCategories:[]}` and `DeletionState.remainingCategories` uses the allowlist `raw_events,derived_knowledge,embeddings,financial_records,connectors,backups` with nullable `blockedAt`.

`jcs-sha256-v1` hashes UTF-8 RFC 8785 canonical bytes of exactly `{changeKind,content,sourceOccurredAt,sourceUpdatedAt}`. Unknown timestamps become null; no NFC/NFD normalization, delivery IDs, deviceObservedAt or transport metadata enter that object. JSON property sorting uses UTF-16 code units, numbers use ECMAScript JSON serialization, and SHA-256 is lowercase hexadecimal. `fixtures.json` publishes literal canonical strings, UTF-8 hex and real hashes, including accents, combining characters and surrogate pairs. Source sequence is positive signed int64 text; item/title/body/batch limits count UTF-8 bytes, not characters. JSON Schema structural checks are supplemented by verifier checks for byte limits, int64 bounds, matching fingerprint, coordinate ranges, interval order and external-embedding policy consistency.

Wire identity is owner + provisioned source instance + durable sourceObservationKey, with separate delivery UUID and producer revision UUID/sequence. Android notification key and existing `notif:<key>` idempotency keys cannot replace this identity; a diagnostic UUID cannot prove a revision. Key reuse after removal requires a persisted new lifecycle generation. Exact delivery replay returns the stored receipt; new delivery for the same producer revision points to the existing revision; changed content/sequence under reused identities conflicts. Arrival order cannot replace producer order, and A-B-A retains all revisions. Tombstone removal preserves previous content and never infers payment cancellation.

Initial enrollment stays out-of-band controlled administration: issuer binds owner, device, scopes and source identities to a revocable hashed opaque token; v2 bodies cannot choose owner. Public enrollment, rotation and logout wire APIs are not invented in this bundle. v1 legacy credentials require registry mapping and matching compatibility headers. v1 `/api/v1/capture/notification` remains separate: its key-only idempotency and arbitrary-2xx acknowledgement cannot drain a v2 queue. Capability failure holds v2 items; any v1 mode needs its own visible limitation and flag. Empty source selection means capture none, and source creation defaults disabled with external models/embeddings denied until explicit consent. Existing mobile selection fallback is not proof of that consent.

401 blocks delivery for reauthentication; 403 blocks the relevant source/operation; foreign IDs return 404; 409 conflicts and 422 fingerprint/contract failures need attention rather than new identity retries. 429/503 honor Retry-After with identity-preserving backoff; a lost acknowledgement or 5xx may follow a commit and must replay unchanged identity. A durable acknowledgement requires supported version plus matching deliveryId, producerRevisionId and contentFingerprint; a malformed 2xx remains pending. Batch success/failure variants are exclusive, ordered by `index`, with per-item transactions. Malformed items return `deliveryId: null` plus a per-item error and index; valid items still process.

Device clocks are source evidence, never server ordering authority; requests require explicit RFC3339 offsets and responses use UTC. Unknown source times remain null; producer sequence determines effective revision recency. No client timestamp automatically confirms facts. Retention defaults in the PRD still require privacy approval, including acknowledged outbox 24h, bounded pending queue, backend deletion/default retention and backup expiry. Disable capture does not silently delete evidence; tombstones block access and stale processing before asynchronous cleanup. External permission is the intersection of all supporting sources, checked at dispatch and response.

Money remains decimal text, grouped by original currency with separate refund adjustments. Confirmed UYU/USD exponent is two; ambiguous/unsupported/pending evidence is excluded rather than silently converted. Backend owns exact totals and any explicitly requested dated FX result; mobile displays the approved rate ID, provider, asOf and original currency and cannot apply a fixed reference rate. Amounts cap at 18 integer plus 6 fractional digits, FX rates at 12 fractional digits, the ISO registry version is pinned in capabilities, rounding is half-even, and transaction/adjustment DTOs are published in this revision.

Standalone validators were generated with Ajv 2020-12 and bundled with their runtime dependencies/licenses; verification requires Node only and never installs dependencies. Maintainer generators are not run by verification. `SHA256SUMS.json` pins every other bundle file, including the exact `spec.md` snapshot; its own SHA-256 is the bundle approval identifier recorded in B02 evidence. Any byte change changes the approval identifier and requires review. The verifier confirms schema-validator provenance, rejects any still-open decision and confirms that the destructive deletion creation operation stays absent. Pure identity, policy and grounding oracles describe E02/E06/E12 fixture expectations; they do not certify database locking, endpoint authorization, provider transmission, native behavior or synthesis. Stale corrections, deletion replay and every provisional operation still require independent review and runtime tests.
