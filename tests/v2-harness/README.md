# Brain AI v2 offline evaluation

For paired model/prompt/rule configuration comparisons, see [the comparison workflow](COMPARISON.md). It reuses this harness's network boundary and metrics helpers, and adds a small synthetic interpretation corpus, acceptance policy, and case-level regression reports without changing E01–E12 release gates.

This is an offline gate runner, a synthetic corpus, and a read-only adapter for the current extraction code. It does not claim that the v2 product or the later phase gates pass. The initial extraction oracle is machine-authored and all labels explicitly await independent adjudication. E02–E12 currently report missing application instrumentation rather than passing a simulator.

```powershell
npm run test:v2 -- --suite E01,E02,E03,E04,E05,E06,E07,E08,E09,E10,E11,E12
npm run eval:v2 -- --dataset tests/fixtures/v2/index.json --offline
node --test tests/v2-harness/harness.test.mjs
```

No database server, port, API key, dotenv file, provider subscription, or network access is required. The inherited environment is checked before application imports; remote database/provider URLs, production targets, and local database names without `test`/`isolated` are rejected. An isolated local URL such as `postgres://localhost:55432/brainia_test` is accepted as configuration but **never connected to** by this offline runner. The actual connection sentinel follows `tests/pglite-setup.mjs`. Fetch, HTTP, HTTPS, TCP, TLS, and UDP are blocked before the adapter imports. Provider calls use a deterministic stub returning an empty response, never the expected answer. A denied network attempt fails the entire run even if an adapter catches it. This is accidental-network protection for reviewed adapters, not a sandbox for hostile JavaScript.

Exit codes: `0` means all selected assertions and evidence gates passed; `1` means a measured quality breach, unsafe target, invalid argument, integrity failure, or adapter exception; `2` means required observations/adjudication/instrumentation are unavailable. FAIL takes precedence over BLOCKED. The first product baseline intentionally exits `1`; CI must retain that failure until the application satisfies the oracle. Missing labelers, native devices or PostgreSQL tests must never be relabelled PASS to make CI green.

`--suite` accepts `all`, one suite, or comma-separated E01–E12. `--split` accepts `all` (default), `train`, `calibration`, or `held-out`. Even an individually selected split does not establish release-wide coverage. Reports default to `tests/v2-harness/artifacts/latest.json`; `--report` accepts a JSON filename directly in that artifact directory. The checked-in first-run baseline is `artifacts/baseline-evaluation.json`; do not overwrite it. `artifacts/before-checkout.json` records the exact dirty checkout, file hashes, machine, redacted flag names, and migration-file fingerprint before corpus/application adapter implementation. It already includes the baseline-capture helper and early command logs; no product changes were made. An installed PostgreSQL schema, deployment and APK were unavailable and are reported as unavailable, not inferred from migrations.

## Corpus maintenance and provenance

`tests/fixtures/v2/index.json` pins twelve JSONL files by SHA-256; `index.sha256` pins the index itself. Version `2.0.0-synthetic.1`, seed `2101`, has 13,820 synthetic cases: E01 500, E02 250, E03 200, E04 100, E05 100, E06 180, E07 2,000 (20 schedules × 100 repetitions), E08 200, E09 100, E10 10,000, E11 90, and E12 100. Every suite uses exact 60/20/20 splits with disjoint source-template, merchant, reference and purchase families. E01 includes 200 multi-amount, 100 currency-ambiguous, 50 generic-title, 50 multilingual and 100 balance-only notifications. Value spans refer to UTF-16 offsets in the body string (JavaScript slicing). Amount expectations are decimal strings. No real personal data is included.

The input index and files are integrity checked before adapters execute. The loader rejects duplicate IDs, split leakage, wrong ratios, missing scenarios, insufficient counts, invalid spans, identifying account/email content, path traversal and changed bytes. The sanitizer audit separately checks that localized separators, bare-dollar ambiguity, and synthetic reference relationships survive removal of email/account content. It is an audit for this synthetic corpus, not an authorization to import personal samples or a general PII detector.

`generate.mjs` is an explicit maintenance command, never part of tests/evaluation. Running `node tests/v2-harness/generate.mjs` rewrites the synthetic corpus and hashes; it must not be used to change expected answers in response to failures. Any future corpus or label change requires a new reviewed dataset version and a new immutable baseline. Independent reviewers must set case label status to `adjudicated`, record their identities and preserve unresolved ambiguities. Finance identity, grounding and episode membership require two distinct labelers and a separate adjudicator. E08 requires human relevance labels; synthetic queries are only a seed. Current empty labeler arrays are deliberately blocking.

The generated families are synthetic templates, not a claim of natural-language diversity or real-world accuracy. E06 is a seed matrix for owners/devices/branches, not proof that the final endpoint inventory is complete. E11 omissions use synthetic object names pending B09's authoritative catalog manifest. E09 has seed overlap/timezone/user-decision cases pending human episode membership labels. E10 has simulated transport expectations, not native execution evidence.

## Application adapters and future evidence

`--adapter tests/v2-harness/<reviewed-adapter>.mjs` selects a repository-local adapter. Export `revision` and `async evaluate(caseInput, context)`. The runner passes `{id, suite, scenario, input}`, never labels or expected answers; context provides the provider stub and `retrievalDocuments(size)` iterator. The default adapter imports actual classification/entity/financial-candidate functions and observes E01. An unavailable capability returns `{blocked: 'specific reason'}`. Exceptions are failures. Adapters should produce observations from application execution or independently reviewed immutable evidence; they must never echo the oracle.

Expected output keys are documented in each fixture. The runner recursively compares required fields, decimal totals and exact lists. `*Minimum` fields require a measured number at least the threshold, `*Maximum` and `recoveryWithinMs` require a nonnegative number at most the threshold. Missing fields fail. For E08, return `retrievedIds`, `exactRetrievedIds`, `baselineMrr10`, `baselineNdcg10`, `sqlTotal` and `forbiddenResults`; recall, ANN/exact ratio and ranking regression are computed by the harness from labelled relevant IDs. Relevance labels are not sent to the adapter. The retrieval iterator lazily constructs 1k/10k/100k deterministic corpora with historical relevant evidence at the beginning, including evidence outside the newest 1k at larger scales. Denied-owner rows remain present to test filtering.

Reports include exact-case numerator/denominator and Wilson 95% intervals, one-sided 95% upper bounds for zero observed errors, source/language/split slices, per-field extraction precision/recall and unknown-currency abstention. Observation latency measures only harness adapter work; production stage latency and live cost reduction remain unmeasured. Provider cost is zero because the network is denied. Counts of synthetic observations do not establish statistical independence or release accuracy.

E06/E07/E11 require a separate real PostgreSQL environment matching the deployed major version, restricted runtime roles, and the specified concurrency/crash/restore instrumentation. PGlite cannot supply that evidence. This offline runner deliberately blocks certification of those suites even with a simulated adapter. E10 consumes native receipt/report evidence only after the mobile worker supplies immutable, independently verified device artifacts with release APK hashes; it remains blocked in this early offline interface. No native test is run here and no mobile repository is accessed. A later reviewed evidence importer must validate those artifacts before lifting the corresponding instrumentation block. Q10 additionally needs an explicit human approval ID and backup/restore proof; an E11 fixture pass cannot authorize deletion.

## Verification and rollback

`npm run lint`, `npm run build`, and `npm run test:isolated` are existing repository checks. The isolated runner discovers only top-level `.test.ts` files; use the explicit Node command above for this `.mjs` infrastructure suite. New scripts do not change the existing default test list. Build emits the repository's normal ignored `dist/` output. No migrations, live workers, cleanup, deployment or provider commands are used.

All B01 source changes are under the two reserved test directories plus two script additions in `package.json`; the coordinator separately authorized `docs/reports/v2/B01-b71c4cc.md`. Rollback consists of removing the two script additions and these newly added test assets after preserving evidence. No database migration or application behavior change needs reversal. Independent verification is still required; the implementer's self-tests are not sole phase acceptance evidence.
