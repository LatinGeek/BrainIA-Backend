## Defect-to-fix map

### N1 — `GET /digests` summarized every owner's evidence

**Fix**
- `src/storage/digests.ts`: `loadDigestData` now accepts `ownerId`. When scoped, the event/metrics window adds `coalesce(r.owner_id, r.client_id) = $n` and the related-insight query adds `insight_runs.owner_id = $n`. Ownerless global rows do not match a scoped caller. An unscoped caller (`ownerId` null/undefined: admin/global or disabled local mode) keeps the previous global behavior.
- `src/storage/digests.ts`: `createKnowledgeDigest` accepts and forwards `ownerId`.
- `src/routes/digests.ts`: resolves `ownerScope(request)` once and passes it both to digest data selection and to `insertDigestRun`.

**Regression test**: `B06/N1 digest generation only summarizes caller-owned evidence`
- Creates one owner-a event/insight and one owner-b event/insight with unique markers, calls `GET /digests` as owner-a over a window covering them.
- Asserts owner-a's marker is present and owner-b's event marker, insight query/summary, and insight id are absent.

### N2 — `GET /insights?q=` resolved a foreign entity

**Fix**
- `src/storage/entity-repository.ts`: `resolveEntityMatches` accepts an optional `ownerId`. The query path (entity text, alias text, approximate name) adds `e.owner_id = $n or (e.owner_id is null and e.type in ('domain','concept'))` when scoped. Public taxonomy remains matchable.
- `src/storage/agent-inspect.ts`: the query path passes `ownerId: input.clientId` into `resolveEntityMatches`; the injected dependency type was widened accordingly.
- `src/routes/entity-resolve.ts`: passes `ownerScope(request)` into resolution as defense in depth; the existing canonical post-filter remains.

**Regression test**: `B06/N2 insight query resolution cannot match a foreign entity`
- Creates an owner-b merchant entity with a unique name, calls `GET /insights?q=<marker>` as owner-a.
- Asserts `matchedEntityId`/`canonicalEntityId` are null, `supportingEntities` is empty, and the response body does not contain the owner-b entity id.

### N3 — `POST /knowledge/feedback` mutated foreign rows

**Fix** (`src/storage/data-controls.ts`)
- `recordKnowledgeFeedback` now verifies target ownership inside the transaction before any update or feedback insert. Foreign targets return `null`; no row and no `knowledge_feedback` entry is written.
- Ownership rules when scoped:
  - `entity`: `owner_id = caller`, or public `domain`/`concept` taxonomy;
  - `insight`: `insight_runs.owner_id = caller`;
  - `candidate`: `owner_id = caller`, or legacy `owner_id is null and client_id = caller`;
  - `event`: `owner_id = caller`, or legacy `owner_id is null and client_id = caller`;
  - `fact`: `owner_id = caller`, or legacy `owner_id is null and client_id = caller`;
  - `relation`: `owner_id = caller`, or legacy null owner whose endpoint entity is caller-owned.
- The entity merge branch additionally requires the canonical target to be caller-owned/public taxonomy. The categorize branch additionally requires the parent to be caller-owned/public taxonomy.
- `src/routes/privacy.ts`: a `null` result from `recordKnowledgeFeedback` is translated to `404 feedback_target_not_found` instead of returning an empty 200.

**Regression test**: `B06/N3 knowledge feedback cannot mutate foreign entities or insights`
- `rename` on an owner-b entity as owner-a returns 404; the entity value stays unchanged and the description is not overwritten.
- `reject` on an owner-b insight as owner-a returns 404; `feedback_status` stays null.
- Asserts no `knowledge_feedback` row exists for either foreign target.

### N4 — financial creation accepted a foreign `accountId`

**Fix** (`src/storage/financial-transaction-repository.ts`, `src/routes/financial-transactions.ts`)
- `assertAccountCurrency` now takes `ownerId` and rejects an account whose `owner_id` differs from the scoped caller with `Financial account not found` before any insert.
- `insertManualFinancialTransaction` and `createPendingFinancialTransaction` pass `input.ownerId`.
- `createBalanceAdjustment` filters the account lookup by `owner_id = caller` when scoped.
- `updatePendingFinancialTransaction` accepts the caller owner and applies the same account check when the account is changed.
- Creation and pending-update routes map the not-found case to `404 financial_account_not_found`; no balance or row change occurs.
- `PATCH /financial/transactions/:id` now pre-checks any provided `accountId`/`destinationAccountId` against strict account ownership before updating.
- Unscoped (disabled local/test) behavior is unchanged: `ownerId` undefined keeps the previous permissive path.

**Regression test**: `B06/N4 financial creation rejects a foreign account and leaves balances untouched`
- Creates an owner-b account, then attempts a manual transaction and a pending transaction as owner-a referencing it.
- Both return 404; no `financial_transactions` or `pending_financial_transactions` row is created for that account; owner-b's account balance remains `0`.

### Conditional item — legacy `owner_id IS NULL` financial account/pending rows

Closed for scoped callers rather than left shared:
- `listFinancialAccounts` and `listPendingFinancialTransactions` now require `owner_id = caller` when scoped.
- `accountOwnedBy`/`pendingOwnedBy` route pre-checks require exact owner equality.
- Manual/pending creation and balance adjustment reject null-owner accounts when the caller is scoped, so ownership is never guessed.

Consequence: legacy null-owner accounts/pending rows are now visible/mutable only through an unscoped admin path until a reviewed backfill assigns ownership. They are no longer mutually visible to owners A and B. No data was rewritten or quarantined by this change.

## Remaining limitations

- **Ownerless background generation remains global** for `/cron/daily-insights` and the empty-body `/insights/daily` path (`src/storage/proactive-insights.ts`). Those paths call `createKnowledgeDigest` without an owner, so they keep the intentional unscoped behavior and can summarize multiple owners; their insight/digest runs remain owner-null. This is outside the scoped `GET /digests` defect but is a carried risk.
- **N2 id path**: the `resolveEntityMatches` id branch remains unfiltered for direct storage callers; `/insights?id=` uses the owner-filtered `listEntities` result, and `/entities/resolve` still post-filters. Query resolution is now SQL-filtered.
- **N3 public taxonomy**: renaming/categorizing/merging a public `domain`/`concept` entity remains possible for an authenticated owner by existing design. Only personally owned rows are protected.
- **N4 event-ingested finance**: `createFinancialTransaction` used by event ingestion still does not write `owner_id`; list/detail reads retain the event-evidence owner fallback for those legacy rows. This was not changed to avoid breaking event-linked finance flows.
- **Legacy null-owner accounts/pending**: now hidden from scoped callers rather than shared, but not backfilled. Admins using an unscoped credential still see them; a reviewed backfill is required to assign ownership.
- RLS is still not wired into request routes; `withOwnerTransaction` remains an isolated foundation. E06/E11 remain BLOCKED (270 cases). Real PostgreSQL concurrency/role persistence/restore remain BLOCKED; all evidence is PGlite.
- `/operations/*`, `/semantic/*`, `/agent/*`, and background workers were not exhaustively re-probed in this remediation.
