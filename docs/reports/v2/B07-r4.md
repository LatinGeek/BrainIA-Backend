## R4 — per-entity source policy in inspect lineage

### Root cause

`loadInspectEntityLineage` checked owner, `privacy_status` and
`processing_allowed` per linked event, but not the owner's per-source egress
policy. A graph neighbour backed by a source with `send_to_llm = false` was
therefore reported as an eligible entity. Its event was merged into the
`lineageEvents` array passed to `authorizeModelDispatch`, and that single denied
source caused a `source_llm_denied` decision for the **whole** inspect request.
The result was zero provider dispatch and `summary: null`, even when the root
and other neighbours were fully allowed.

### Fix

`loadInspectEntityLineage` now resolves the effective owner-scoped policies for
every linked source in one query (`loadOwnerSourcePolicies`) and requires
`enabled && sendToLlm` for each event **before** the event can make its entity
eligible. Missing policy rows count as a denial, matching
`authorizeModelDispatch`'s external-egress rule.

Consequences:

- a denied-source neighbour is not in `eligibleEntityIds`, so it is removed from
  the external graph, relations, paths and entity list by the existing
  `restrictGraphForExternalDispatch` / search-result filter;
- the denied neighbour's events are not added to `lineageEvents`, so the
  authorization decision covers only allowed evidence;
- the allowed root and allowed neighbours still dispatch exactly once;
- the pre-existing fail-closed behavior is preserved: a denied or unlineaged
  **root** still produces `lineageBlocked`, no dispatch and no summary;
- a single ineligible event still blocks its entire entity (conservative).

The local, non-model inspection payload is unchanged and still shows the full
owner-visible graph.

## Regression added

`B07 inspect omits a denied-source neighbour without poisoning allowed dispatch`
builds:

- root entity with an allowed-source event and policy (`sendToLlm = true`);
- allowed neighbour with an allowed-source event and policy;
- denied neighbour with an event whose policy has `sendToLlm = false`;
- `root -> allowed` and `root -> denied` relations.

It asserts:

- exactly **one** provider call (previously zero);
- the root and allowed-neighbour markers are in the dispatched body;
- the denied neighbour's description marker and entity id are absent from the
  dispatched body (no denied marker);
- the local inspection graph still contains the denied neighbour for owner
  display.

The existing regression for an unlineaged neighbour and the entity-only denied
root test remain unchanged and passing.
