## R3 — digest related-insight selection now uses the shared predicate

`loadDigestData` in `src/storage/digests.ts` selected `insight_runs` with only a
direct `insight` tombstone check:

```sql
and not exists (
  select 1 from deletion_tombstones tombstone
  where tombstone.target_type = 'insight' and tombstone.target_id = insight_runs.id
)
```

That allowed a legacy entity-only insight, already ineligible on every other
derived read path, to be returned as `relatedInsights`, copied into
`highlights[0]` (via `buildHighlights`), sent in the digest synthesis prompt, and
persisted inside a new digest's response/summary.

The query now applies the same predicate used by `insight-repository.ts`,
`digest-repository.ts`, `hybrid-retrieval.ts`, `search-repository.ts` and
`data-controls.ts`:

```ts
import { derivedRunReadEligibilitySql } from "./search-repository.js";
...
and ${derivedRunReadEligibilitySql("insight_runs", "insight_runs")}
```

Because `loadDigestData` is the single source for both `relatedInsights` and the
`relatedInsights` field placed in the synthesis prompt, the fix covers the whole
echo path at once:

1. `createKnowledgeDigest` response `relatedInsights` — excluded;
2. `highlights` derived from the latest related insight — excluded;
3. synthesis `userPrompt` / provider body — excluded;
4. the digest run persisted by `GET /api/v1/digests` — excluded from its
   request/response/summary;
5. `GET /api/v1/digests/history` — cannot serve the hidden summary through a
   newly generated run.

No migration or `contracts/schema/manifest.json` regeneration was needed: the
predicate and its `revalidated_at` columns already exist from r3.

## Remaining limitations / not closed

- **Acceptance is not claimed.** Only this residual was fixed; independent
  B11 re-verification is still required.
- **Over-invalidation by design.** The predicate hides all pre-tombstone
  insight/digest runs for an owner after any tombstone, including unrelated
  runs. Digest `relatedInsights` inherits that conservative behavior.
- **Revalidation has no operator workflow.** `revalidated_at` is honored but not
  set by any route/UI.
- **Text/prose resurrection remains undetectable by id.** A live-lineage run may
  still carry prose copied from deleted content.
- **PGlite only.** Real PostgreSQL RLS/multi-connection behavior and `pg_dump`
  restore remain BLOCKED; E06/E11/E12 remain BLOCKED with no adapter credit.
- **Restore gate remains deployment-configured** with operator-asserted ledger
  completeness.
- **Graph cache is in-process only**; cross-instance caches rely on the 30 s TTL.
- **Finance preservation** still protects only transactions with another
  `financial_transaction_events` row.

No commit, dependency install, migration, manifest regeneration or production
database was used.
