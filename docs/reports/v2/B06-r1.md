## What changed

### `src/auth.ts` — principal model
- `Principal = { ownerId, clientId, mode, scopes, authenticated }`; attached to `FastifyRequest` by the API hook.
- Client-key mode resolves `ownerId` from the authenticated key mapping, never from a caller-supplied owner header.
- Global key mode is now **admin-only with no owner** (`ownerId: null`, `scopes: ["admin"]`). Data routes return `403 owner_scope_required` instead of inheriting an arbitrary client id.
- `x-brainia-owner-id` / `x-owner-id` are rejected with `403 owner_header_not_accepted` whenever auth is enabled.
- Fail-closed: `BRAINIA_REQUIRE_AUTH=true` (or `NODE_ENV=production` / `VERCEL=1`) with no configured credentials returns `503 auth_not_configured` for every `/api` request.
- Cron secret resolves a `cron` principal with `jobs` scope only.
- `ownerScope(request, config?)` returns the authenticated owner; the legacy disabled mode (tests/local only) remains unscoped so existing local flows do not break. `requireOwnerId` and `requireScope` are available for strict call sites.

### Route/query scoping
Now owner-scoped at the HTTP boundary and in the repository query:
- `/events` list, `/events/:id`, `/events/:id/reprocess`, `/events/:id/reconcile-financial` — `raw_events.client_id`.
- `/search` and `/retrieval/hybrid` — events, entities, relations filtered by owner; public taxonomy remains visible.
- `/financial/transactions` list and detail; `/financial/accounts`; `/financial/pending-transactions`; transaction/account/pending mutations perform an ownership pre-check before mutating.
- `/privacy/*` and `/knowledge/feedback` — owner comes from the principal, not from a raw header.
- `/semantic/*` — owner required; backfill no longer scans all owners when the caller is scoped.
- `/intelligence/*` — owner comes from the principal; the strict error handler maps authz failures.
- `/entities`, `/relations`, `/insights`, `/agent/inspect`, `/client-diagnostics`, `/entities/:id/profile` — owner-scoped reads/writes.
- Removed every direct `request.headers[x-brainia-client-id]` trust in routes.

### Database
- `migrations/20261017110000_owner_rls.sql`:
  - creates `brainia_runtime` (NOLOGIN), grants schema/table/sequence access;
  - `public.brainia_current_owner()` reads the transaction-local setting;
  - enables RLS and creates `owner_isolation` policies on 38 personal tables;
  - adds a read-only public-taxonomy policy on `entities`;
  - keeps the owner mapping/quarantine/split ledgers default-deny.
- `withOwnerTransaction(ownerId, fn, { enforceRls })` in `src/storage/postgres.ts`:
  - `set_config('brainia.owner_id', owner, true)` — transaction-local, no pooled leak;
  - optional `set local role brainia_runtime` for RLS enforcement.
- Schema contract regenerated: **45 migrations / 1709 catalog objects**; `problems: []`.

### Tests
`tests/v2-authorization.test.ts` (4 tests):
1. auth required + unconfigured → `503 auth_not_configured`;

## Security notes

- Confirmed defect fixed: routes previously trusted `x-brainia-client-id` directly. They no longer do.
- Confirmed defect fixed: a global API key no longer implies an arbitrary owner.
- Conditional risk remaining: unscoped endpoints listed above can still return cross-owner data until B06 completes; they are not claimed as fixed.
- Mitigating control: production fails closed without credentials, and RLS default-denies ownerless access once `brainia_runtime` is used.
- `NOT VALID` ownership FKs from B05 remain unvalidated; validation requires approved backfill evidence.
