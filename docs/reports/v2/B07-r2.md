## D1 — agent inspect entity-only bypass

`src/storage/agent-inspect.ts`:

- New `loadInspectEntityLineage({ entityIds, ownerId })` resolves the events linked to the root entity and every graph node through `event_entities` and `event_relations`.
- The lineage is marked ambiguous when it is empty, contains a missing/foreign owner, is not `privacy_status = 'standard'`, or is not `processing_allowed`.
- `inspectKnowledge` now merges search-returned events with entity/graph lineage events before calling `authorizeModelDispatch`. If lineage is blocked, the authorization is `null` and `generateNaturalLanguageSummary` is never called.
- With a real entity and no event lineage at all, external synthesis also fails closed. This also closes the “data-bearing purpose with zero sources” hole for this route.

Consequence/property: a denied-source entity still resolves and returns deterministic graph/search data, but its summary is `null` and zero provider transport calls occur. An allowed-source entity follows the normal single-dispatch path.

## D2 — proactive insight embedding

`src/storage/proactive-insights.ts`, `src/storage/embeddings.ts`:

- `upsertEmbedding` accepts an optional caller-supplied `PrivacyAuthorization | PrivacyDenial`. When supplied, that authorization is the only gate (including its policy version) and is not re-created from an empty source set.
- `synthesizeTopInsightCandidates` passes its `insightAuthorization` (the conservative denied-owner-source intersection) to the insight embedding. If synthesis was denied, the deterministic summary is embedded locally and never sent to the embedding provider.
- The daily digest embedding path now applies the same conservative rule: any denied owner source forces the local vector.

## D3 — `evaluate-laya` direct provider call

Actual path: `src/scripts/evaluate-laya.ts` (the task referred to `scripts/evaluate-laya.ts`; this repository keeps scripts under `src/scripts/`).

- Without `LAYA_EVALUATION_OWNER`, `LAYA_EVALUATION_EXTERNAL_APPROVED=true` and a documented `LAYA_EVALUATION_REASON` (minimum 10 characters), the script prints a refusal and exits non-zero before any provider call.
- With the opt-in, the query is owner-scoped and each row must pass `authorizeModelDispatch` for `event_classification` before dispatch; denied rows are skipped. Title/body are redacted through the authorized policy before serialization.
- The regression spawns the script without environment approval and asserts exit code 1 and the refusal message, so it cannot silently dispatch raw events.

## D4 — derived-work policy versions

`src/storage/insight-repository.ts`, `src/storage/digest-repository.ts`, `src/storage/hybrid-retrieval.ts`:

- `insertInsightRun` / `insertDigestRun` now write `policy_version`. Callers may supply it; otherwise it records the owner's current maximum source-policy version.
- `listInsightRuns` / `listDigestRuns` / `load*` return `policyVersion` and a computed `stale` flag when any owner policy version is newer than the run's stored version.
- Hybrid retrieval excludes stale `insight_runs` / `digest_runs` candidates using the same comparison.
- The existing migration columns are used; no new migration and no manifest change.

## D5 — embedding provenance

`src/storage/embeddings.ts`:

- External embedding dispatch now requires `EMBEDDING_API_KEY`, `EMBEDDING_API_URL` **and** a non-empty `EMBEDDING_MODEL`. Without a model id the deterministic 192-d local vector is returned and labelled `brainia-semantic-hash`.
- External vectors carry the configured model id, so local and external vector spaces are no longer mislabelled.

## Latent reconciler cross-owner input

`src/storage/semantic-reconciler.ts`:

- `loadReconciliationNodes(ownerId)` filters personal entities by owner while still allowing global domain/concept taxonomy rows.
- The reconciliation authorization also treats every denied owner source as part of the conservative intersection.

## Remaining limitations

- Real PostgreSQL concurrency, pool-role persistence, RLS deployment and restore remain **BLOCKED**; PGlite proves isolated engine behavior only.
- E08/E10 (and the other v2 suites) remain **BLOCKED** with no adapter credit.
- Missing source-policy rows still use the legacy permissive compatibility default. This remediation did not change that policy decision; it remains a separate architecture/backfill decision.
- The reconciler now uses an owner filter and conservative denied-source list, but entity descriptions still lack a persisted per-entity source lineage. If finer evidence is required, that lineage must be added by the entity/graph owner.
- `evaluate-laya` is still an operator tool by design. Its opt-in gate and per-row authorization prevent ungated bulk egress, but it requires an explicitly approved owner and does not run in CI with provider access.
- Derived-run staleness is computed from the owner's maximum source-policy version. If a policy row is later deleted rather than version-bumped, the comparison cannot detect it; policy deletion is not part of the current model.
- Ownerless cron paths remain deterministic/local; the embedding gate now keeps them local, but owner propagation for cron remains a separate carried risk.
- No production provider, external network, mobile file or production database was used.

## Not closed / not claimed

- No acceptance claim. A re-verification should re-run the denied/ambiguous/allowed entity-only probes, the owner-invoked proactive embedding probe, the `evaluate-laya` refusal, the policy-bump staleness check, and the unset-model provenance check.
- The broader missing-policy permissive default and real-PostgreSQL/RLS certification remain outside this remediation.
