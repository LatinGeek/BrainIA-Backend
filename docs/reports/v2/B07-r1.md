## What changed

### 1. Central dispatch authorization (`src/storage/privacy.ts`)

`authorizeModelDispatch(db, {ownerId, purpose, sources, evidence, eventIds})` is the single pre-dispatch gate. It fails closed when:

- `ownerId` is missing/blank (`missing_owner`);
- `purpose` is missing or outside the closed `PRIVACY_PURPOSES` list (`missing_purpose` / `unknown_purpose`);
- any evidence event id is absent, has no owner, belongs to another owner, is not `privacy_status = 'standard'`, or has `processing_allowed = false`;
- any contributing source policy has `enabled = false` or `send_to_llm = false`.

The result is a `PrivacyAuthorization` carrying the owner, purpose, source intersection, policy version, redaction flags, event ids and an asynchronous `recheck()`. `recheck()` reloads live policies/evidence and requires the policy version to be unchanged.

`stillAuthorized()` is the post-wait/pre-publish helper.

### 2. Central network boundary (`src/storage/deepseek.ts`, `src/storage/embeddings.ts`)

- `generateNaturalLanguageSummary` now requires a `privacy` authorization. Missing/denied authorization returns `null` without calling `fetch()`.
- `generateEmbedding` requires authorization for external embeddings; without it the deterministic 192-d local vector is used. Denied/revoked embedding dispatch never calls the provider.
- A provider semaphore (per-owner 1, global 4 by default) is acquired before dispatch. Authorization is rechecked **after** the semaphore wait and again **after** the provider response, before returning/publishing content.
- Provider non-2xx bodies are no longer stored in `model_call_audits`, logged, or included in thrown errors. Error audit metadata is limited to HTTP status/error name.
- Denial logs are metadata-only: reason, purpose, source count. No owner id, source name, query text, prompt, evidence or provider body.

### 3. Caller coverage (inventory + gates)

| Boundary | Payload class | Gate added |
|---|---|---|
| `classification-assistant.ts` → `generateNaturalLanguageSummary` | event title/body/raw fields, tags, confirmed corrections | owner + purpose `event_classification` + source policy + optional audit event id |
| `classification-assistant.ts` → `jev.ts` | same event payload to Typesafe JEV | indirect gate: wrapper authorizes first and passes `allowModel:false` when denied |
| `semantic-enrichment.ts` → `requestSemanticJson` | title/body, subjects, canonical context, hierarchy | owner + purpose `semantic_enrichment` + source + audit event id; recheck before returning decision |
| `semantic-reconciler.ts` | entity values/descriptions, parents, evidence counts | owner + purpose `semantic_reconciliation`; recheck before graph writes |
| `agent-inspect.ts` | query text, entity, graph, search results | owner + purpose `agent_inspect` + query + event evidence; no summary when denied |
| `digests.ts` | event titles/ids/sources/kinds/timestamps, insight queries/summaries | owner + purpose `knowledge_digest_synthesis` + event sources + intersection; denied mixed sources keep deterministic content only |
| `proactive-insights.ts` | candidate titles/explanations/evidence/actions | owner + purpose `proactive_insight_synthesis`; conservative denial when any owner source denies egress |
| `intelligence.ts` | objective, history, evidence text, aggregates, feedback | owner + purpose plan/synthesis + evidence source/event eligibility; artifact marked `stale` on denial; recheck inside `complete()` |
| `embeddings.ts` (`upsertEmbedding`, `refreshEventEmbeddings`) | event/entity text, insight/digest summaries | owner + purpose `embedding` + source policy + event ids where derivable |
| `hybrid-retrieval.ts` → `generateEmbedding` (query text) | retrieval query text | external query embedding has no purpose token, so it fails closed to the local vector (see limitations) |

Mixed-source rule: the authorization is the intersection of contributing source permissions. A denied source blocks the whole externally dispatched summary; digest insight lineage is handled conservatively because `insight_runs` does not persist source lineage.

### 4. Versioned policy and invalidation

Migration `20261017130000_privacy_policy_versioning.sql` (additive only):

- `source_processing_policies.policy_version bigint not null default 1`;
- trigger increments `policy_version` when an egress-relevant field (`enabled`, `send_to_llm`, redaction flags, `retention_days`, `owner_id`) changes;
- `knowledge_embeddings.policy_version`, `insight_runs.policy_version`, `digest_runs.policy_version`;
- metadata-only `privacy_policy_changes` audit table;
- indexes; existing rows are preserved and initialised to version 1.

Application-side, a policy change marks the owner/source embeddings `policyStale`, stamps the new version, inserts a `privacy_policy_changes` row and bumps the in-process derived-cache generation. No derived row is destroyed.

## What is proven (PGlite, current checkout)

- Denied source, foreign-owner evidence and missing owner/purpose produce zero provider `fetch()` calls; no forbidden marker appears in any transmitted body.
- A policy revocation while a second call is queued prevents the queued dispatch, and the already-in-flight call returns `null` instead of publishing stale content.
- Mixed allowed/denied sources are denied by intersection; a digest over them produces no model output and zero transport calls.
- Allowed input still dispatches and returns content; the payload is redacted per policy.
- Provider error bodies are neither logged nor echoed in the thrown error.
- A policy change increments the version, marks existing embeddings stale, records the metadata-only change row and invalidates the in-process cache generation.
- Existing isolated suite behavior is preserved: 137/137 pass, including the new 5 tests.

These are isolated engine and spy-transport proofs, not production enforcement.

## What is BLOCKED / not proven

- Real PostgreSQL concurrency, pool-role persistence, RLS deployment behavior and restore remain **BLOCKED** (`realPostgresConcurrency: BLOCKED`, `isolatedPgDumpRestore: BLOCKED`).
- v2 harness suites are **BLOCKED** with no adapter credit: E06 180/180, E12 100/100, E08 200/200, E10 10 000/10 000.
- `hybrid-retrieval.ts` is outside the reservation and calls `generateEmbedding` without a purpose token. External query embeddings therefore fail closed to the deterministic local vector until the retrieval owner supplies a purpose/authorization. No query payload is dispatched.
- `semantic-reconciler.ts` route/job callers are outside the reservation and do not pass `ownerId`. Model reconciliation now returns `privacy_denied` until owner propagation is implemented by that owner.
- Ownerless cron/empty-body daily insight/digest paths in `proactive-insights.ts` do not dispatch a model; they keep deterministic content. Owner propagation for cron remains a B06 carried risk.
- `jev.ts` still owns its direct HTTP call and was not edited (outside reservation). It is gated indirectly only through `maybeEnhanceClassification`; a direct caller of `classifyWithJev` would rely on its existing policy check, not the new owner/purpose gate.
- `src/scripts/*` direct model callers (`validate-live-intelligence`, `probe-deepseek-semantic`, `evaluate-laya`, `remote-smoke`) are outside the reservation and do not supply a privacy authorization; they now fail closed. They were not used as verification.
- Missing policy rows still use the legacy permissive `DEFAULT_SOURCE_POLICY` for compatibility. The architecture's stricter "legacy missing-policy must not inherit permissive defaults" is not fully implemented; a reviewed policy decision/backfill is required.
- Proactive insight candidates do not persist reliable source lineage, so any denied owner source conservatively blocks synthesis for that owner.
- `source_processing_policies` still has a `(client_scope, source)` unique key; an owner-specific upsert can collide with a legacy anonymous row. This migration did not change the key.
- RLS is still not wired into request routes; the new policy tables/columns are additive and the runtime still uses the legacy table-owner role.
