## Remaining limitations / not closed

- **PGlite only.** Real PostgreSQL RLS, multi-connection role behaviour,
  deadlocks and `pg_dump` restore are still BLOCKED. E06/E11/E12 remain BLOCKED
  with no adapter credit.
- **Restore gate is deployment-configured.** `src/server.ts` runs the gate only
  when `BRAINIA_RESTORE_MODE=true`. A deployment that omits the flag is a
  normal start, not a restore. The function itself was tested; a real server
  startup/process exit test was not run.
- **Lease/liveness of the restore ledger is operator-asserted.** An empty ledger
  can only pass when the operator explicitly sets `BRAINIA_RESTORE_VERIFIED` and
  `BRAINIA_RESTORE_LEDGER_COMPLETE`. The gate cannot independently prove that
  the live ledger is complete.
- **Hybrid post-filter is route-level.** `/retrieval/hybrid` is filtered before
  return. Internal direct callers of `hybridRetrieve` that request relation,
  insight or digest object types would still need their own call to
  `filterEligibleRetrievalResults`; current internal callers request only
  event/entity types.
- **Window invalidation is deliberately conservative.** A digest whose window
  contains a deleted event is invalidated even when the digest’s prose was not
  about that event. This over-invalidates rather than serving a stale summary.
- **Text/ID trigger matching.** Replay guards detect persisted target ids in
  JSON/text. A writer that inserts an unlinked, ownerless derived row with no
  reference to the deleted id (and, for digests, a window outside the event)
  is not detectable by the trigger. The application read paths still require a
  visible/eligible event before serving content.
- **Graph cache is in-process only.** Cross-instance caches rely on the 30-second
  TTL; deletion invalidates the deleting process.
- **Finance preservation** still protects only transactions with another
  `financial_transaction_events` row; an unlinked transaction is treated as
  sole-evidence and deleted with the anchor event.
- **Legacy anonymous local mode** remains limited to fully anonymous rows and is
  not an authenticated-owner path.
- Real provider dispatch, mobile clients against the legacy routes, and a live
  PostgreSQL restore remain unverified.

## Rollback

The new migration is additive. Rolling back application code leaves the extra
guards and triggers in place; old writers will still be unable to recreate
tombstoned derived content. Drop the new triggers/functions only in a reviewed
destructive rollback after preserving the ledger. Do not recreate tombstones
from a backup; the tombstone ledger remains the restore-time source of truth.
