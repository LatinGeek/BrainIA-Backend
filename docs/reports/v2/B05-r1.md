## What was added

### Migration `20261017100000_owner_identity.sql`
- `client_owner_mappings` — legacy `client_id` → approved `owner_id`, with approval provenance and evidence. Statuses: `approved`, `quarantined`, `split`.
- `owner_quarantine` — additive quarantine ledger keyed by `(table_name, row_id)`. Statuses: `quarantined`, `released`, `remediated`. Never deletes the underlying row.
- `entity_owner_splits` — idempotent record of a shared personal entity split into per-owner scoped identities.
- `owner_id` columns added to: `raw_events`, `entities`, `relations`, `event_entities`, `event_relations`, `event_semantic_anchors`, `entity_aliases`, `entity_merges`, `entity_review_queue`, `financial_transactions`, `financial_transaction_events`, `financial_accounts`, `pending_financial_transactions`, `knowledge_facts`.
- Owner indexes on each personal table (owner + natural access path).
- Composite ownership FKs (`NOT VALID` over legacy rows, enforced for every new write) from `event_entities`, `event_relations`, `event_semantic_anchors`, `financial_transaction_events` to `raw_events(id, owner_id)`.
- `entities_public_taxonomy_owner` trigger — public taxonomy (`type in domain/concept`) can never carry an owner.
- `event_entities_owner_guard` trigger — a personal event cannot link an entity with a different owner; missing owner is filled from the event.
- `owner_row_visible(table, row_id)` SQL helper used by ordinary scoping.

### `src/storage/ownership.ts`
- `ownerInventory` — per-table owner key classification; flags every personal table without an owner key.
- `recordOwnerMapping`, `quarantineRow`, `releaseQuarantinedRow` — additive, idempotent ledger operations.
- `ownerVisiblePredicate(table, qualifiedId)` — validated allowlist + required outer alias; rejects unqualified expressions so the correlation cannot bind to `owner_quarantine.id`.
- `isOwnerRowVisible` — calls the SQL helper.
- `backfillOwnership` — idempotent backfill that:
  1. records legacy→owner mappings (explicit or identity default, marked `requires_owner_confirmation`);
  2. assigns `raw_events.owner_id`;
  3. inherits owner into event children, anchors and financial evidence links;
  4. assigns `knowledge_facts.owner_id`;
  5. splits shared personal entities per owner with scoped mapping;
  6. assigns single-owner canonical personal entities and relations;
  7. assigns finance owners only when evidence proves exactly one owner;
  8. clears and audits owner leakage on public taxonomy;
  9. quarantines unresolved accounts, pending items, ownerless transactions and ambiguous multi-owner entities.
  It never updates existing ids, amounts, currencies, evidence counts or classification rows.
- `src/scripts/backfill-ownership.ts` + `npm run backfill:ownership`. Dry-run by default; `--apply` and `--mapping=legacy:owner,...` are explicit.

### Tests
`tests/v2-ownership.test.ts` (5 tests):
1. inventory covers all 14 personal tables with an owner key;
2. idempotent backfill maps owners, splits a shared entity, preserves transaction ids/amounts/evidence, and a second run is a no-op for splits;
3. quarantined financial account is invisible to `isOwnerRowVisible` and the scoped predicate until released;
4. public taxonomy rejects an owner (trigger) and a cross-owner event edge is rejected;
5. quarantine insertion is idempotent and unsafe/unqualified visibility predicates are rejected.

## Limits and follow-ups

- RLS is **not** enabled in this task; B06 must apply owner-scoped queries and the restricted DB role first.
- Split copies use an owner-qualified `normalized_value` (`::owner:<md5>`) with `metadata.ownerScopedOriginalNormalizedValue`. This avoids changing the global entity uniqueness contract before `upsertEntity` is owner-aware; B06 must thread the owner into entity upserts so future re-use targets the scoped copy.
- The legacy identity default (`legacy client_id == owner_id`) is recorded with `requires_owner_confirmation: true`. Production mapping approval is still a human decision.
- `NOT VALID` composite FKs must be validated only after backfill evidence is reviewed and approved.
- PGlite proves sequential semantics only; real PostgreSQL concurrency, role/RLS behavior and production migration/rollback remain unverified.
- E06/E11 remain BLOCKED; this report does not claim them.
- Historical pre-snapshot write attribution is not provable; post-snapshot scope is recorded below.
