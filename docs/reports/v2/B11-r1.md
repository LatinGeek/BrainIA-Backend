## Required-step mapping

1. **Tombstone before asynchronous cleanup.** `tombstoneDeletion` writes the
   tombstone and records the root lineage in one transaction, then
   `quarantineDeletedTarget` makes the event and its derived families ineligible
   in that same transaction. `deletePersonalData` commits that step first and
   runs `applyDeletionTombstoneCleanup` in a second transaction. A cleanup
   failure leaves the tombstone and quarantine flags in place.
2. **Lineage traversal.** Cleanup covers event/entity/fact embeddings and vector
   text, knowledge facts, classification corrections and decisions, semantic
   candidates/observations/decisions/anchors, insight and digest runs and
   candidates, intelligence artifacts/revisions/confirmations/feedback, client
   diagnostics, relation/entity links, graph traversal cache, and finance
   correlations. A canonical finance row is deleted only when the deleted event
   is its sole supporting observation; otherwise the evidence link is removed,
   the anchor moves to remaining evidence and `evidence_count` is recomputed.
3. **Summaries/insights after deletion.** Insight/digest content is redacted and
   removed, affected candidates are expired, remaining intelligence artifacts
   with other dependencies are marked stale with content cleared, and their
   revisions/feedback are not served.
4. **Restore before traffic.** `applyDeletionTombstonesAfterRestore` reads the
   ledger, replays each tombstone into the restored database inside one
   transaction, runs cleanup, and returns `trafficBlocked` only when no
   tombstoned event is still standard/processable.
5. **Owner isolation / B06-B07.** The target lookup is owner-scoped. Foreign or
   owned-target-without-a-principal deletion returns `null` and writes nothing.
   Legacy local mode can delete only a fully anonymous event (`owner_id` and
   `client_id` both null); it cannot reach an owned row. Dispatch remains
   owner/purpose/source/evidence gated and now also denies `target_tombstoned`.
6. **Backup expiry.** The default is 30 days, in
   `DELETION_BACKUP_EXPIRY_DAYS`, the migration column default, and the restore
   result. Restores of older backups return `expiredBackups` and must be
   reviewed manually.

## Rollback and compatibility

- The migration is additive. Rolling back application code leaves the tombstone
  tables and guard triggers in place; old writers will still be unable to
  re-create tombstoned derived content. Drop the new tables/triggers only in a
  reviewed, explicitly approved destructive rollback after preserving evidence.
- If a new read/publication flag is introduced later, disable it rather than
  deleting tombstones. Tombstones are the restore-time source of truth.
- Old backups: retain at most 30 days by policy; a restore older than the window
  must be blocked for manual review. `applyDeletionTombstonesAfterRestore` must
  run before the restored database is exposed to traffic.
- No existing migration, table, row, constraint or API contract bundle was
  rewritten.

## Limitations / not closed

- **PGlite only.** This is not real PostgreSQL RLS, multi-connection, role or
  restore evidence. E06/E11/E12 remain BLOCKED.
- **Restore wiring is not installed in server startup** because `src/app.ts` /
  server code is outside the B11 write reservation. The function exists and is
  tested, but deployment must call it before accepting traffic.
- **Derived insight/digest/artifact discovery is heuristic** (JSON text
  containment plus persisted lineage). It deliberately over-invalidates rather
  than under-deletes; a future canonical evidence-link table would make this
  exact.
- **Graph cache is in-process only.** DB graph rows/relations are removed or
  hidden through links; cross-instance caches rely on their TTL and the
  invalidation call in the deleting instance.
- **Finance preservation** only protects transactions with another
  `financial_transaction_events` row. Transactions whose evidence was never
  linked are treated as sole-evidence and deleted with the anchor event.
- **Legacy anonymous local mode** is preserved for existing local tests. It is
  limited to fully anonymous rows and is not an authenticated-owner path.
- **Entity rows are hidden rather than always deleted**, because an entity may
  be shared with other observations. Their embeddings are removed/stale and
  entities with no remaining event link stay hidden.
- Real provider dispatch, real PostgreSQL restore and E06/E11/E12 gate
  instrumentation were not available and are not claimed.
