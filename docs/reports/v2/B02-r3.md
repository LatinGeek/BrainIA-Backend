## Six owner-confirmation items

Each value is retained because it does not contradict the PRD/data model, but none is pinned by an owner decision. They still require explicit owner confirmation before approval.

| # | Value | Why confirmation is required |
|---|---|---|
| 1 | Activity `signalTypes`: `still,walking,running,cycling,driving,transit,unknown` | The PRD/data model treat activity as an interpreted fact but define no signal-type enum. The closed set is a chosen product taxonomy; `transit`/`driving` collapse platform modes. |
| 2 | Event `eventType`: `purchase,payment,income,transfer,refund,adjustment,delivery,appointment,communication,other` | The data model has `canonical_events.event_type` but no closed enum. `payment` vs `purchase` boundaries and the `other` fallback need product confirmation. |
| 3 | Fact `field` allowlist and `visibility: visible|internal` | The data model defines `extracted_facts.field`, typed value, spans and validation status, but not this 18-value allowlist and not a `visibility` column/value set. |
| 4 | Episode membership roles: `primary,supporting,context` | The data model has `episode_memberships.role` and the normative contract lists `role`, but neither pins these three values. |
| 5 | Connector `returnRoute`: `brainia://connectors/email/callback` | The mobile scheme `brainia` is real, but the exact route is newly chosen and its mobile handler is not implemented or exercised. Mobile owner confirmation is required. |
| 6 | Currency registry label `ISO4217-CLDR-45` with confirmed `USD`/`UYU` subset | The PRD/data model require an ISO currency exponent registry and confirm only UYU/USD summary semantics; they do not pin CLDR 45. The runtime registry binding and any registry expansion remain owner decisions. |

## Remaining conditions and limits

- `from <= to` and the 366-day maximum cannot be expressed in portable JSON Schema query parameters. They are encoded in `FinancialSummaryQuery` semantics enforced by `contracts:verify`, documented as `x-query-constraints`, and must also be enforced by the future HTTP handler.
- `CurrencyRegistry` is the confirmed `USD`/`UYU` subset, not the full ISO 4217 table. Any expansion requires an owner decision and new fixtures.
- The callback redirect fixtures validate the contract shape and `brainia://` Location allowlist; they do not exercise a real OAuth provider or mobile route handler.
- All 13 provisional operations remain `implementationBlocked: true`; `POST /api/v2/deletions` remains absent; capability gates stay `false`; M07, email/activity capture and connectors remain blocked.
- No application, test, migration, mobile, ledger or approval file was written. `approvals.json` still has no B02-r3 entry.
- This report is not an approval and must not be used as one. Independent review plus a hash-bound owner approval entry are still required.
