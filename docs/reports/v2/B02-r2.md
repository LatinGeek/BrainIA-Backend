## Field decisions

### Shared

- Pagination: `Cursor` is an opaque 1-512 character string; pages return `nextCursor: string|null`; `limit` is 1..100.
- Errors: existing code set extended with `unsupported_currency` and `oauth_state_invalid`. `details` is optional but, when present, a strict union discriminated by `kind`: `field_errors` (`field`, `code`, `expected`, `actual`), `retry` (`retryAfterSeconds`), `conflict` (`conflictId`), `blocked_category` (`blockedCategory`). No free-form object.
- Timestamps: RFC3339 with explicit offset on requests; response timestamps are UTC `Z`; nullable source timestamps mean unknown, never now.
- Money: decimal strings with at most 18 integer digits and 6 fractional digits; `ConversionRate` allows 12 fractional digits; currency is a 3-letter ISO 4217 code; capabilities pins `currencyRegistryVersion: "ISO4217-CLDR-45"`; unsupported codes use `unsupported_currency`.
- Raw payloads: notification raw accepts only `packageName,title,body`; receipt/wallet raw accepts only `amount,currency,merchant,transactionType`; note/email/activity/location raw must be empty. Unknown and credential-shaped keys are rejected.

### Confirmed wire decisions encoded

- `Activity`: `activityMarker` `observed|inferred`; closed `signalTypes` `still|walking|running|cycling|driving|transit|unknown`; `interval {start,end}` with `end>=start`; `confidence` 0..1. Capability stays false.
- `Email`: structured `{address,displayName?}`; address format email and max 320 characters; displayName max 256. Capability stays false.
- Attachments: opaque `{refId,provider?,mimeType?,sizeBytes?,sha256?,expiresAt?}`, max 20.
- `Capabilities`: bearer-protected, no credentials; `features {observationRevisions:true,decimalFinance:true,email:false,activity:false,location:false,episodes:false,connectors:false}`; `currencyRegistryVersion` added.
- `Receipt.processing` is `queued` only.
- Batch: 1..50 items; results carry ordered `index`; malformed items return `deliveryId: null` plus an error; valid items still process.
- `Fact`: strict union on `factType` (`string|decimal|currency|timestamp|boolean|entity_ref`) with typed `value`, `field` from the closed allowlist `merchant,amount,currency,occurred_at,posted_at,description,account,category,reference,title,sender,recipient,location,activity,entity,quantity,unit,status`, paired UTF-16 `start`/`end` (`end>start`), `excerptHash`, confidence 0..1, `extractorVersion`, `modelRevision`, `visibility: visible|internal`, validation/correction status and typed uncertainty candidates. No generic placeholder.
- Summary filters: `from`/`to` required, `from<=to`, 366-day maximum range, conversion requires `fxRateId`, no defaults.

### Operation-specific decisions

- Observation detail exposes identity, latest revision, revision count, content type, stage, stage time, timestamps, tombstone flag and a revisions cursor. Stage enum: `captured|queued|running|succeeded|review|retry_scheduled|dead_letter|cancelled`.
- Revision history exposes immutable content, producer identity/sequence, fingerprint, source/device/received timestamps and `evidenceIds`; hidden/deleted items are excluded by the server.
- Event exposes type, lifecycle, version, occurrence interval/uncertainty, merge pointer, evidence with role/strength/active, uncertainty candidates, interpretations distinguished from evidence, and review reasons. Event types: `purchase|payment|income|transfer|refund|adjustment|delivery|appointment|communication|other`. Lifecycle: `observed|authorized|pending|declined|posted|review|reversed|expired|cancelled`.
- Episodes use the normative DTO plus list filters and a detail extension (`priorRevisionIds`, `activeCorrectionIds`). Member roles: `primary|supporting|context`.
- Transactions expose nonnegative base `amount`, explicit `currency`/`currencyStatus`, lifecycle, merchant, account, evidence count/revision count, evidence roles (`charge|refund|reversal|authorization|settlement|context`), strength and separate signed `adjustments[]`. List requires `from`/`to`.
- Corrections use a strict `oneOf` by target type and allowlisted field: fact `fact_value`; event `event_type|lifecycle|occurred_start|occurred_end`; transaction `merchant_label|category|account_id|amount|currency|occurred_at|posted_at|kind|lifecycle`; episode `membership_include|membership_exclude|split|merge`. `expectedVersion` is mandatory. `scope=rule` requires a non-null `ruleMatch`. Response includes `affectedCount` and `reviewReasons[]`.
- Export returns `{snapshotId,items[{type,id,record}],nextCursor,expiresAt}` with type allowlist `observation|revision|fact|correction|event|transaction|episode|artifact`. Expired snapshots return 409 `export_snapshot_expired`.
- Queries accept `{query,maxEvidence 1..30,externalSynthesisAllowed,filters{sourceInstanceIds?,from?,to?,types?}}`. 202 returns `{queryId,status}`; `QueryResult` is a strict status union (`queued|running|completed|review|failed`) with typed structured totals, evidence, claims, limitations, coverage and failure. Uncertain claims are labelled; answers/evidence are absent before verification.
- Email authorize accepts `provider:"gmail"`, allowlisted `returnRoute` and `historyDays 1..90`; response contains an https authorization URL, state expiry, least-privilege Gmail readonly scope and no token/verifier. Callback consumes one-use state and redirects to the allowlisted route; invalid state uses `oauth_state_invalid`.
- Connector revoke accepts `{expectedVersion,deleteCapturedData}` and returns `{connectorId,status:"revoked",version,revokedAt,deleteCapturedData,deletionId}` with idempotent owner-bound replay.
