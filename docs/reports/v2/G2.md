## A.5 Regressions and residual risks from the condition round

No functional regression was observed: the isolated suite is 202/202, the independent probe is 26/26, E01 improved, and the v1-compatible tests still pass. The following are residual risks or verification gaps introduced/exposed by the round, not proven failures:

- **RLS is opt-in.** `BRAINIA_DB_ENFORCE_RLS` defaults off because ingestion still persists only `client_id`. With the flag off, routed reads keep the table-owner bypass. With it on, legacy `client_id`-only rows may become invisible (availability, not a cross-owner leak).
- **Only reads are owner-transacted.** Financial/privacy mutations, graph traversal execution, `/semantic/*`, `/agent/*`, `/operations/*`, resolve/alias/merge routes and workers remain on their existing scopes (B06 D2/D3/D5).
- **Export under enforcement.** `GET /privacy/export` can return an empty `sourcePolicies` array under `BRAINIA_DB_ENFORCE_RLS=true` (B06 D4) - visibility loss, not a leak.
- **Fence scope is narrow.** Only classification and financial-correlation main work is fenced; embedding, insight, retention, backup verification and semantic enrichment still rely on completion-time fencing (B08).
- **Revalidation is storage-only.** `revalidateDerivedRun` has no route or operator authentication; policy-stale runs cannot be revalidated and must be regenerated (B11 r5).
- **Mobile follow-ups are not independently verified.** The 221-check mobile conformance run and settings changes come from implementer reports; the verifier reports are older.
- **Test evidence file restored.** `tests/v2-harness/artifacts/latest.json` is a tracked generated artifact. The required `test:v2` run rewrote it; it was restored to HEAD so this gate did not leave a test-artifact diff. The command output above is the record of that run.
