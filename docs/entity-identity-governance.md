# AI-governed entity identity

## Purpose

The raw event is evidence. It is not the knowledge graph.

An extracted title, notification sentence, amount, timestamp, identifier, card suffix, or truncated fragment must never become a visible graph node merely because an extractor returned it. A visible node represents a durable concept or identity that can be understood independently from the event that introduced it.

## Required identity contract

Every visible graph node must have all of the following:

1. A concise canonical name selected by the semantic model.
2. A standalone description generated by the semantic model.
3. An entity type and a normalized canonical name.
4. Identity confidence at or above the semantic root confidence threshold.
5. A validated path to a governed life-domain tree.
6. Provenance linking the identity back to its raw evidence and model.

The Explore graph only exposes identities whose `identity_source` is `ai`, `ai_seed`, or `user` and whose description is non-empty.

## Naming rules

- Names must communicate what the node is without needing the source event beside it.
- Event titles and sentences cannot be copied as names for activity, email-message, or financial-event nodes.
- Amounts, timestamps, account or card suffixes, opaque IDs, package names, action words, and truncated text are invalid names.
- Proper nouns for people, merchants, applications, services, and accounts must remain factual. The model may normalize casing, remove transaction noise, and select the canonical form, but may not invent or embellish the identity.
- If the evidence does not support a safe name, the proposed entity is discarded and the event remains available for later reprocessing.

## Description rules

- The description must explain what the entity represents in the user's graph.
- It must be understandable without reading the original event.
- It may summarize supported context but must not introduce unsupported claims.
- Relation rationale is separate from entity description: the former explains why two nodes connect; the latter defines one node.

## Ingestion behavior

1. Store the incoming event unchanged as raw evidence.
2. Extract candidate facts for model context only.
3. Ask the semantic model for canonical identity, description, hierarchy path, and associations.
4. Validate the model response and reject malformed, generic, copied, or low-confidence identities.
5. Persist and expose only governed identities.
6. Keep ungoverned evidence outside Explore and queue it for reprocessing when the model is unavailable.

## Existing data

Legacy entities remain stored for provenance but are excluded from Explore until an AI identity pass supplies a valid name, description, and hierarchy. Reprocessing must preserve event evidence, aliases, transaction links, and merge history while promoting or merging the governed identity.
